# پشتیبان‌گیری و بازیابی PostgreSQL 17

این راهنما برای محیط بومیِ درخواستی نوشته شده است؛ نصب PostgreSQL و اجرای این مراحل هنوز انجام نشده‌اند. پیش از اتصال با اعتبارنامه، ساخت دیتابیس مقصد یا بازیابی، مجوز مشخص مالک لازم است. هیچ فرمانی نباید دیتابیس موجود را حذف یا بازنویسی کند.

## محل نگهداری و دسترسی

دادهٔ فعال، فایل‌های محیطی، فایل گذرواژه و پشتیبان داخل OneDrive یا مخزن کد قرار نگیرند. مسیر پیشنهادی پشتیبان: %LOCALAPPDATA%\GourmetAsie\backups، با دسترسی محدود Windows. پشتیبان می‌تواند شامل اطلاعات کارکنان و هش رمزها باشد؛ فایل custom به‌خودی‌خود رمزنگاری‌شده نیست. نگهداری نسخهٔ جدا و رمزنگاری‌شده برای خرابی دیسک باید با مالک برنامه‌ریزی شود.

دستورهای زیر نمونه‌اند. نام حساب‌ها و دیتابیس‌ها پیشنهادی هستند و هنوز ایجاد نشده‌اند. ابزارها با مسیر کامل فراخوانی می‌شوند تا نیازی به تغییر PATH سیستم نباشد. --password رمز را به‌صورت تعاملی می‌پرسد؛ رمز در آرگومان دستور یا گزارش نوشته نشود.

## ساخت پشتیبان

پس از تأیید مالک و آماده‌شدن حسابِ مجاز برای خواندن داده، ابتدا مسیر پشتیبان و فضای دیسک را بررسی کنید. مسیر مقصد باید نام تازه داشته باشد تا فایل قبلی بازنویسی نشود.

```powershell
$pgBin = 'C:\Program Files\PostgreSQL\17\bin'
$backupFile = Join-Path $env:LOCALAPPDATA ('GourmetAsie\backups\gourmet-dev-' + (Get-Date -Format 'yyyyMMdd-HHmmss-ffff') + '.dump')
if (Test-Path -LiteralPath $backupFile) { throw 'فایل مقصد از قبل وجود دارد.' }
& "$pgBin\pg_dump.exe" --host=127.0.0.1 --port=5432 --username=gourmet_backup --dbname=gourmet_dev --format=custom --password --file=$backupFile
if ($LASTEXITCODE -ne 0) { throw 'پشتیبان‌گیری ناموفق بود؛ فایل را معتبر فرض نکنید.' }
& "$pgBin\pg_restore.exe" --list $backupFile
```

pg_dump از یک دیتابیس نسخه می‌گیرد؛ نقش‌های سراسری و تنظیمات سرویس داخل آن نیستند و باید جداگانه، بدون ذخیرهٔ راز در مخزن، مستند شوند. خروجی --list نیز می‌تواند نام اشیای دیتابیس را نشان دهد و نباید بی‌دلیل منتشر شود.

## آزمایش بازیابی

فقط پس از تأیید مالک: یک حساب نگهداریِ مجاز باید دیتابیس آزمایشی تازه و خالی، مثلاً gourmet_restore_test، با مالک مناسب بسازد. از دیتابیس فعال برنامه به‌عنوان مقصد استفاده نکنید. فقط پشتیبان مورد اعتماد خود پروژه بازیابی شود؛ محتوای پشتیبان می‌تواند SQL اجرا کند.

```powershell
& "$pgBin\pg_restore.exe" --host=127.0.0.1 --port=5432 --username=gourmet_migrator --dbname=gourmet_restore_test --password --no-owner --no-privileges --exit-on-error --single-transaction $backupFile
if ($LASTEXITCODE -ne 0) { throw 'بازیابی آزمایشی ناموفق بود.' }
```

عمداً از --clean و --create استفاده نشده است. پس از بازیابی، جدول‌ها، روابط، شمارش داده، تاریخچهٔ migration و چند سناریوی برنامه در مقصد آزمایشی بررسی شوند. مجوزهای نقش محدود برنامه به‌علت --no-privileges جداگانه و مطابق سیاست تأییدشده اعمال شوند. بازیابی تا انجام این بررسی‌ها موفق اعلام نشود. حذف دیتابیس آزمایشی نیز فقط با مجوز مشخص انجام شود.

مراجع رسمی: [pg_dump در PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgdump.html) و [pg_restore در PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgrestore.html).
